# CARO_HMI Trend Viewer — Spec Deltas

**Purpose:** One-line entries for divergences from `hmi_trend_viewer_spec.md` during implementation. Propagate to target docs at session end, then delete entries.

- Removed orphaned `evictRange` (interface, implementation, 5 tests in useTrendData, mock + 7 assertions in TrendChartContainer); fixed handoff drift in notes #16 (FIFO→ring), #21 (evictRange ref), #25 (evictAll addendum), and file-map lines (both occurrences).
- Added `MAX_BUCKET_S` constant to `@caro/db` (replaces literal 14746), re-exported from barrel; duplicated in `level.ts` with cross-ref comment; derived `MAX_VIEWPORT_SPAN_MS`; clamp applied in `useTrendMode` reducer (`zoomApplied`, `panApplied`, `endPickerCommitted`); `rangeExceeded` state added to `useTrendData`; "Range too wide" overlay added to `TrendChartContainer`; route-level early bucketS validation added before `getTrendTile` call.
- Added proactive bucketS skip in `useTrendData` main effect: sets `rangeExceeded=true` and returns before constructing tiles when `derivedBucketS > MAX_BUCKET_S` (eliminates 400 spam from stale `dataViewport`); `rangeExceeded` overlay now renders footer (`footerJsx`) below the message so presets/EndPicker/Live button remain visible for recovery.
- Over-range state now renders TrendChart with empty `AggregateSeriesData` (`n=0`, empty `series`) behind a bold red banner, preserving axes/grid/legend/x-axis interactions (wheel-zoom and drag-zoom can recover without reaching preset buttons).
- Extracted `isViewportOverRange` helper in `useTrendData`; gated `ensureCovered` on it (before `active.length === 0` check) so pan-extension fetches are also suppressed when the viewport is over-range, eliminating "dynamic fetch failed" 400s that bypassed the main-effect proactive guard.
- Replaced two separate over-range gate blocks (main-effect early-return and ensureCovered guard) with a single `gatedFetchTile` useCallback wrapper around `fetchTile`; all four fetch sites now delegate through the wrapper, making the over-range check impossible to bypass when a fifth site is added; `CLIENT_OVER_RANGE` sentinel error used for silent no-op catches at each site.
- Pre-epoch tile filter: `tilesForViewport` now filters `startTime < 0n` from both visible and prefetch arrays (TS_BUCKET_ORIGIN_MS alignment pushes left-prefetch before Unix epoch on epoch-adjacent viewports); `ensureCovered` candidate filter adds `t.startTime >= 0n` guard; `gatedFetchTile` adds defensive `CLIENT_PRE_EPOCH` sentinel check before the `CLIENT_OVER_RANGE` check (silent skip, no `rangeExceeded`, no `batchHasRangeExceeded`); 2 new tests added (level.ts epoch-adjacent, useTrendData pre-epoch ensureCovered).
- `TrendChartContainer` rangeExceeded branch: replaced `emptyData` (`n=0`, empty series) with `placeholderData` (`n=2`, `bucketSMs=Number(span)`, one null-filled series entry per tagId); uPlot auto-fits its xScale to the two stub x-values at `modeViewport.start` and `modeViewport.end`, preventing the `[0,1]` fallback that caused negative-timestamp feedback on subsequent wheel events; 2 tests updated/added (placeholder bounds + x-values invariant).
