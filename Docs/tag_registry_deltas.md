# Tag Registry — Spec Delta

**Purpose:** Divergences between tag-registry implementation and its spec documents.
Read once at session start. Add entries when implementation diverges from spec.

---

- **Editor page layout — 3-column** — §16.3 describes a 2-area right panel (Templates Tree top, Fields Panel bottom). Actual layout is now 3 independent columns: System Tree | Properties (FieldsPanel) | Templates (TemplatesTree). Each column scrolls independently. Propagate to tag_registry_spec.md §16.3 and tag_registry_bootstrap.md.
- **Templates panel label** — §16.4 header label was "All Templates"; now "Templates". Propagate to tag_registry_spec.md §16.4.
- **ValidationPanel height cap** — §15.1 does not mention height constraints. Panel is now capped at `max-h-[50vh]` with the message list scrollable and the "Validation" header sticky. Propagate to tag_registry_spec.md §15.1.
- **Dirty indicator styling — tree nodes** — §16.2 specifies orange bold (`text-orange-700 font-semibold`) for changed/new child instances in the System Tree. Now bold italic, no color change (`font-semibold italic text-gray-800`). Same change applied to template leaves in the Templates Tree (§16.4). Propagate to tag_registry_spec.md §16.2 and §16.4.
- **Dirty indicator styling — fields panel** — §16.5 specifies `font-semibold text-orange-700` for dirty field labels and inputs; override fields `text-blue-600` unchanged; inherited clean defaults `text-gray-700` unchanged. Dirty fields now use `font-semibold italic text-gray-700` (no orange). Checkbox dirty accent removed. Propagate to tag_registry_spec.md §16.5.
- **Validation tree highlighting** — New feature, not in spec. Tree nodes in the System Tree whose subtree contains validation errors/warnings receive a colored left border and background tint: `border-l-4 border-red-500 bg-red-50` for errors, `border-l-4 border-yellow-400 bg-yellow-50` for warnings. Error severity beats warning. Computed in `EditorPage` as `pathSeverityMap` from `msg.ref.tag_path` prefixes; passed down via props through `AssetTree` → `TreeNode`. Selection (blue border/bg) takes visual priority over tint. Add new §16.2.x to tag_registry_spec.md.
- **tag_name resolution** — `resolveRegistry` computes `tag_name` (dot-joined asset names of meta levels where `In_Tag_Name === true`, root→leaf) and includes it on `ResolvedTag`; `validateResolvedTags` enforces `TAG_NAME_EMPTY` and `TAG_NAME_TOO_LONG` (≤40 chars); `MAX_TAG_NAME_LENGTH` and `IN_TAG_NAME_FIELD` added to `constants.ts`. Propagate to tag_registry_spec.md and tag_registry_api_spec.md.
- **In_Tag_Name seeding** — all 36 template JSON files seeded with `In_Tag_Name: { field_type: 'Boolean', default: true/false }` as the first field entry; true for `parameter`/`tag` types, false for all others (system, module, Group, and custom types Beam/Cooling/HMI/Power/Power_Supply/RF/Scan). Propagate to tag_registry_spec.md.
- **DUPLICATE_TAG_NAME validation** — `validateResolvedTags` now detects two or more resolved tags that share the same `tag_name` (case-insensitive, entire-registry scope) and emits one `'error'`-severity `DUPLICATE_TAG_NAME` per offending tag; `DUPLICATE_TAG_NAME` added to `ERROR_CODES` in `constants.ts`. Propagate to tag_registry_spec.md and tag_registry_api_spec.md.
