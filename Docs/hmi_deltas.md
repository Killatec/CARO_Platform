- **2026-08-02:** New `@caro/widgets` widget `SpectrumChart` — generic `number[]`-tag uPlot line chart (bin-index X axis, no frequency mapping yet); adds `uplot` as a direct dependency of `@caro/widgets` (previously zero chart deps there) plus `src/css.d.ts` ambient `*.css` module declaration, mirroring `@caro/trend-chart`'s pattern. Wired into `SpecABox` against `Pole.SpecA.Spectrum`. Live array data flows through the existing generic LKV/WS/`useLiveValue` pipeline unchanged — no server-side work needed.
- **2026-08-02:** `SpectrumChart` — fixed explicit size (default 640×320, up from a 160-tall chart squeezed to the narrow parameter-row column width); dropped the `ResizeObserver` live-resize wiring since size is now a controlled prop, not measured from a fluid container. Added `yMin`/`yMax` props (default 0–1000) — Y axis is fixed range, not auto-scaled, since `Spectrum` has no `eng_min`/`eng_max` to derive one from. `SpecABox` layout changed to a flex row: parameter list on the left, chart beside it on the right (was stacked at the bottom of the single vertical `WIDGET_STACK` column). `SpecABox`'s `SpectrumChart` instance overrides `yMax={2100}`.
- **2026-08-02:** `SpectrumChart` — added drag-to-zoom on both X and Y axes (single rectangular drag, not two separate gestures) via a custom `setSelect` hook + ref-backed scale `range` functions, mirroring `@caro/trend-chart`'s proven pattern (native `cursor.drag.setScale` disabled to avoid the stale-scale race documented there). Double-click resets both axes to full range (0..last bin, `yMin`..`yMax`). Zoom persists across live `setData()` pushes from new spectrum captures.
- **2026-08-10:** `SpecABox` — `Start_Freq`/`Stop_Freq` `NumericSet` rows replaced by a single `Center_Freq` `NumericSet`, matching the tag-registry template change (`Pole.SpecA` now specifies center frequency, not a start/stop band).
- **2026-09-19:** `DbPipeline` writer error logs (incl. "No historian writer") rate-limited to once per 30s burst (errorCount still increments every tick). New `HistorianReconnector` (`historian-reconnect.ts`) retries `pingTimescale()`/`runTimescaleMigrations()` every `TIMESCALE_RECONNECT_MS` (default 30000) while on `NullDbWriter`, and hot-swaps in a `TimescaleDbWriter` + `TimescaleSizeMonitor` via new `DbPipeline.setWriter()` / `HmiTagSource.attachSizeMonitor()` — no restart needed to recover persistence once Timescale becomes reachable. Superseded the old startup TODO for this.
- **2026-09-19:** `DbPipeline` "queue full — dropping oldest entries" warn throttle raised from 5s to 30s (was firing multiple times per historian-error log interval). `index.ts` startup log now also prints one `http://<ip>:<port>` line per non-internal IPv4 interface (new local `getLocalIPs()` helper, `os.networkInterfaces()`), not just the bare port.
