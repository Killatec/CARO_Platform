# CARO HMI — App Anchor

## Quick Start

From monorepo root (starts all 6 dev servers with color-coded output):
```bash
npm run dev
```

Or HMI only:
```bash
# Server (port 3003)
cd apps/caro-hmi/server
npm run dev

# Client (port 5175, proxies /api→3003 and /ws→3003)
cd apps/caro-hmi/client
npm run dev
```

Prerequisites: PostgreSQL running with tag registry populated, Mosquitto on 1883.

## Server Architecture

| Module | File | Purpose |
|---|---|---|
| LKV Cache | `server/src/lkv.ts` | In-memory `Map<tag_id, { value, generation }>`. Generation bumps only on value change (strict equality). |
| Telemetry Intake | `server/src/telemetry-intake.ts` | Transport-agnostic ingestion: LKV writes, watchdog (lastSeen tracking, null-write on timeout), DB pipeline enqueue. Universal entry point for all telemetry via `ingest(moduleId, message)`. Calls `trendDeltaListener(moduleTs, moduleId)` once after every `ingest()`, changed or not; `index.ts` registers `wsServer.handleTrendDelta` via `setTrendDeltaListener`. FAULT status nulls the module's LKV entries, then the frame's values are applied (no early return). Stall → null historian sentinel per trendable tag; recovery → `moduleRecoveredHandler` (REQUEST_SNAPSHOT only, so change-only telemetry refills the LKV; Sets are re-sent only after a re-bind). Full walkthrough: `Docs/platform/CARO_Telemetry_Path_Reference.md` §4. |
| MQTT Bridge | `server/src/mqtt-bridge.ts` | Transport only. On every broker connect (including reconnects): subscribes `caro/+/telemetry`, `caro/+/cmd_ack` and `caro/+/handshake_module`, starts the `/beat` heartbeat (never withheld), and sends REHANDSHAKE to every MQTT module — no command is sent on connect. Telemetry is `JSON.parse`d — **Protobuf is not decoded** — then shape-checked by `parseTelemetry` (`server/src/mqtt-payloads.ts`: a frame without a numeric `timestamp`, string `status` and `tags` array is dropped; bad entries are skipped) and handed to `TelemetryIntake.ingest()`. CMD_ACKs are checked by `parseCmdAck` (one malformed result drops the whole ACK) and go to `CmdController`; drops are logged at most once a minute per module and reason. The `/beat` timer is replaced on each connect and stopped on disconnect. handshake messages go unvalidated to the `onHandshake` handler. Publishes commands to `caro/{module_id}/cmd` and handshake messages to `caro/{module_id}/handshake_backend`, both at QoS1. Known gaps: `CARO_Telemetry_Path_Reference.md` §12. Wire contract: `Docs/platform/CARO_MQTT_Spec.md`. |
| HMI Tag Source | `server/src/hmi-tag-source.ts` | Proxy-based telemetry producer for `module_type='HMI'` tags. Property names derived from `tag_path` (strips module segment, joins remaining with `_`). Publishes to TelemetryIntake on configurable timer (default 250ms). Publishes `Module_Info.Handshake` from `HandshakeController.getStatus()` once `attachHandshake()` is called (the controller is created after it in `index.ts`). Reads 7 Trend_Info values from `DbPipeline` and `TimescaleSizeMonitor` each tick: Trending, Queue_Depth, Rows_Per_Sec, Flush_ms, Dropped_Pkgs, Error_Count, DB_Size. A write to a property with no matching registry tag absorbs instead of throwing (`get` returns `null`) — the registry not having instantiated the HMI/Module_Info/Trend_Info templates (fully or at all) is a normal, permanent state, not a startup race. Each distinct absorbed property name is logged once (`reportedUnknownProps` set); a constructor-time summary logs one honest line only when the module has zero HMI tags at all (`0 HMI tags found in registry`). No maintained list of expected property names — this also means a genuine typo no longer throws, only logs. |
| Duty Tracker | `server/src/duty-tracker.ts` | Wraps telemetry hot paths with `performance.now()` timing. `snapshot(intervalMs)` returns duty cycle as percentage, resets accumulator. Fed into `hmiTags.Telemetry_CPU` via `onBeforePublish`. |
| WS Server | `server/src/ws-server.ts` | Pull-based at configurable tick (default 8 Hz / 125 ms). Per-client generation tracking. SUBSCRIBE → SNAPSHOT → DELTA. JSON encoding. **Trend channel (Step 11):** parallel subscription set for trend deltas. SUBSCRIBE_TREND (trendable tagIds only) → on every ingest of a module, `handleTrendDelta(moduleTs, moduleId)` appends the current LKV value of each of that module's subscribed trendable tags to the client's per-tag outbox (cap 500, drop oldest). Flushed at `TREND_FLUSH_HZ` (default 4 Hz) as `TREND_DELTA { samples: [...] }` frames, with one synthetic sample (server `Date.now()`, current LKV) for each subscribed tag that had none. Values are sent raw; the client coerces booleans. UNSUBSCRIBE_TREND tears down the trend subscription for those tagIds. `PING { ts }` → `PONG { ts }`. Endpoint `/ws`, no auth. `parseTagIdsArray` returns `{ valid, rejected } \| null` — `null` only for a non-array payload (rejected wholesale); an array with some invalid elements subscribes the valid ones and logs the rejected ones by value, across all four message types (SUBSCRIBE/UNSUBSCRIBE/SUBSCRIBE_TREND/UNSUBSCRIBE_TREND). One bad id no longer discards the whole batch. |
| DB Pipeline | `server/src/db-pipeline.ts` | Push-based queue from TelemetryIntake. Peek-then-consume flush with inFlight guard. `TimescaleDbWriter` (or `NullDbWriter` fallback), swappable at runtime via `setWriter()`. `TIMESCALE_DB_TICK_MS` tick (default 500ms); queue max 5000 (`TIMESCALE_DB_QUEUE_MAX`); max 500 entries per flush (`TIMESCALE_DB_MAX_ENTRIES_PER_FLUSH`). Counters clipped at 9999. `queueDepth` is a tick-held pre-peek snapshot; `queueLength` is live. Writer error logs (incl. "No historian writer") rate-limited to once per 30s burst (`errorCount` still increments every tick); "queue full — dropping oldest entries" warn throttled to once per 30s. |
| TimescaleDbWriter | `server/src/timescale-writer.ts` | Wraps `writeTagSamples()` from `@caro/db`. Coerces bool→float, drops NaN/Infinity to null, drops strings to null (logs once per instance). |
| Historian Reconnector | `server/src/historian-reconnect.ts` | Retries `pingTimescale()`/`runTimescaleMigrations()` every `TIMESCALE_RECONNECT_MS` (default 30000ms) while `DbPipeline` is on `NullDbWriter`. On success, hot-swaps in a `TimescaleDbWriter` + `TimescaleSizeMonitor` via `DbPipeline.setWriter()` / `HmiTagSource.attachSizeMonitor()` — no restart needed to recover persistence once Timescale becomes reachable. Started only when the historian wasn't ready at startup. |
| TimescaleSizeMonitor | `server/src/timescale-size-monitor.ts` | Background poll of `pg_database_size()` every `TIMESCALE_SIZE_POLL_MS` (default 30s). Exposes `sizeGB`; started only on the `TimescaleDbWriter` path. Errors held silently (previous value retained); warn logged at most once per hour. |
| Tag Map | `server/src/tag-map.ts` | Loads tag registry from DB. Builds `Map<tag_id, TagDef>`. Reads `unit`, `eng_min`, `eng_max`, `format`, `tag_name` directly from resolved `row.*` columns — never walks meta for these. `module_id` from `meta.find(m => m.type === 'module')` (structural). Accepts pre-fetched `ActiveTag[]` to avoid a second DB call. |
| Trend Snapshot Scheduler | `server/src/trend-snapshot-scheduler.ts` | Ensures every trendable tag gets ≥1 DB row per `TREND_SNAPSHOT_INTERVAL_MS` (default 60s). Piggyback path: arms a per-module flag; consumed at the top of `TelemetryIntake.ingest()` to write a full trendable-tag LKV snapshot (using `message.timestamp` as `moduleTs`) instead of the COV delta. Force-write path: if flag still set at next tick (silent module), calls `forceTrendSnapshot()` directly with `moduleTs = Date.now()`. Runs inside `DutyTracker.track()`. |
| Trends REST Endpoint | `server/src/routes/trends.ts` | Two routes. `GET /api/v1/trends/tile` — v0.9 wire contract: query params `tag_ids` (1..8 csv ints), `start_time` (bigint ms), `end_time` (bigint ms), `bucket_count` (1..2500); dispatch in `@caro/db` `getTrendTile`: raw COV when `span_s × 10 ≤ bucket_count`, otherwise bucketed with `bucketS = round(span/bucket_count)/1000` choosing `tag_samples` (<1 s) / 1s / 10s / 1min / 10min CAG, with watermark-aware fall-through; no trendable-membership check on `tag_ids`; aggregate response carries per-series `value`, `min`, `max` arrays (three-case rule: mixed-null → null, empty-bucket → LOCF'd last × 3, normal → `last`/`bucket_min`/`bucket_max`); raw responses carry `ts`/`value` plus optional `prev: { ts, value }` per series (bounded-prev: most-recent sample in [startTime−5min, startTime), v0.9) — discriminated-union invariant; `source` discriminant (`'raw' | 'tag_samples' | '1s_cagg' | '10s_cagg' | '1min_cagg' | '10min_cagg' | 'mixed'`); bigint→Number conversion at wire boundary via `serializeTile()`; optional gzip via `HMI_TRENDS_GZIP`. Watermark lookups memoized in `@caro/db` with 30s TTL + in-flight dedup (see §4.3 of trend viewer spec). `GET /api/v1/trends/extent` — no params; returns `{ oldestTs: number\|null, newestTs: number\|null }` (hypertable-wide min/max ts). All delegate to `@caro/db` functions. |
| Config | `server/src/config.ts` | Port, MQTT, WS, watchdog, heartbeat, HMI publish, historian reconnect, trend snapshot and trend flush env vars with defaults (`TREND_FLUSH_HZ` outside 1–20 throws at import). `dbTickMs` is read but unused — `DbPipeline` and `TimescaleSizeMonitor` read their own env vars. Also calls `loadEnv()` itself, because it is evaluated before `index.ts` runs. |
| Command Publisher | `server/src/cmd-controller.ts` | `writeValues()` fans SET_VALUES per module, awaits CMD_ACK via `pending` map (1s timeout). `sendCommand(moduleId, cmdStr): Promise<void>` sends an arbitrary command: MQTT → fire + await CMD_ACK via `pendingVoid` map (resolves on empty/all-accepted results, rejects `COMMAND_REJECTED` on device rejection, rejects `TIMEOUT` (504) after 1s); HMI → `cmd_str='RESET'` calls `hmiTagSource.reset()`, any other cmd_str rejects `COMMAND_NOT_SUPPORTED` (400). `sendReset`/`sendResetAll` remain for legacy broadcast reset path. Setpoint store: an operator SET_VALUES writes `commanded_setpoints` (migration 018) — accepted values as `accepted`, every value of a timed-out command as `timeout`, nothing on rejection — and also upserts accepted values into `pending_setpoint_values` (016) with no mode comparison (modes are not built; nothing reads that table). `getModuleSetpoints(moduleId)` returns every Set of the module from `commanded_setpoints`, `null` where nothing is stored; `pushSetpoints(moduleId, setpoints)` publishes them as one SET_VALUES (nulls included) and awaits the ACK, which only upgrades `timeout` rows to `accepted` (keeping `set_by`). There is no startup or recovery re-delivery: the post-CONFIRM push is the only Set delivery. No `set_by` from users (auth not built) and no audit log writes. |
| Handshake Controller | `server/src/handshake-controller.ts` | Backend side of the module handshake (`CARO_MQTT_Spec.md` §7.5). Answers every `HANDSHAKE_REQUEST` from an MQTT-type registry module with a TAG_LIST (`buildTagList`), ignoring (logged once) a payload `module_id` that differs from the topic, a non-MQTT module and a module with no tags; `verifyModuleIdentity()` is a placeholder that always accepts. A CONFIRM answering a TAG_LIST is logged (missing/unknown names), then `getModuleSetpoints` → `pushSetpoints` → `requestSnapshot`. A push with no ACK sends REHANDSHAKE, at most `MAX_PUSH_RETRIES` (3) in a row. State in memory: per module a `HandshakeStatus` code (`getStatus()`, N/A for non-MQTT, NONE before any request, unchanged by a stall) and a `HandshakeDetails` record (`getDetails()`: request identity, TAG_LIST size, CONFIRM lists, push outcome). `CONFLICT` is reserved, not set. |
| Handshake Route | `server/src/routes/handshake.ts` | `GET /api/v1/handshake/:moduleId` → `HandshakeController.getDetails()`; `MODULE_NOT_FOUND` (404) for a non-MQTT module. Contract: `Docs/hmi/hmi_API_spec.md` §5.4. |
| Tag List | `server/src/tag-list.ts` | `buildTagList(tagMap, moduleId)` → `{ tags: [{ tag_id, tag_name, is_setpoint }] (by tag_id), skipped }`. `tag_name` is module-relative, from `moduleRelativeTagName()` in `@caro/tag-registry-shared` — the one function the Tag Defs export also uses, and the one stated exception to never deriving `tag_name` from `meta`. |
| Write Route | `server/src/routes/tags.ts` | Three routes: `GET /api/v1/tags` (tag list); `GET /api/v1/tags/trendable` (trendable subset: `{ tags: [{ tag_id, tag_path }] }`, filtered from `trendableTagIds` set passed at startup); `POST /api/v1/tags/write` (setpoint writes — validates existence, is_setpoint, and number/boolean/numeric-string value; no data_type or module_type check; delegates to `CmdController.writeValues()`, which routes MQTT → SET_VALUES, HMI → `HmiTagSource.setValue()`, other → `MODULE_TYPE_NOT_SUPPORTED` result). `/trendable` handler registered before `/` to prevent route capture. |
| Express | `server/src/app.ts` | Express shell. Mounts `/api/v1/config`, `/api/v1/tags`, `/api/v1/reset`, `/api/v1/commands`, `/api/v1/trends` (gzip-wrapped when `HMI_TRENDS_GZIP=1`). Auth stubbed. |
| Entry | `server/src/index.ts` | Startup sequence: tag rows → tag map → LKV → DutyTracker → TelemetryIntake → HmiTagSource (with DbPipeline + optional TimescaleSizeMonitor) → HistorianReconnector.start() (only if the historian wasn't ready at startup) → MQTT bridge → CmdController → HandshakeController → WS attach → DbPipeline.start() → TrendSnapshotScheduler.start() (if `TREND_SNAPSHOT_ENABLED`) → `mqttBridge.start()` (soft-fail; no setpoint re-delivery after it). Logs a distinct warning (`tag_registry returned no active tags — apply a registry revision first.`) when `getActiveTags()` returns zero rows. Prints one `http://<ip>:<port>` line per non-internal IPv4 interface (`getLocalIPs()`, `os.networkInterfaces()`), not just the bare port. Graceful shutdown stops scheduler and HistorianReconnector before DbPipeline. `DbPipeline` owns its own tick; `config.dbTickMs` is not used. |

## Client Architecture

| Module | Path | Purpose |
|---|---|---|
| Shell | `client/src/shell/` | Header, NavTree, ContentArea. Generic HMI chrome. `Shell.tsx` resolves its page tree at runtime — `useProjectRoot()` → `hmiDefinitionsRegistry` lookup → dynamic `import()`, held in state; `validIds`/initial-id resolution (from URL hash, else the tree's first node) live inside the component (moved out of module scope so they can depend on the loaded tree) and re-derive once the tree resolves. An unregistered or null `projectRoot` resolves to `tree = []`, which `NavTree` already renders as its "No machine config loaded" empty state — no fallback to `demo`. `Header.tsx` shows `projectRoot` in its badge. |
| HMI Definitions | `client/src/hmi-definitions/` | Per-system nav trees and page components, one folder per `PROJECT_ROOT` value (`Narya1`, `demo`). `registry.ts` is an explicit static `Record<string, () => Promise<{ tree }>>` map — not `import.meta.glob` — so a missing tree fails at compile time and a system not currently selected stays out of the loaded chunk (dynamic `import()` per entry). `shared/` holds boxes used across systems; machine-specific boxes stay there until a system's tree outgrows the shared composition (see `Narya1/pages/SystemOverviewPage.tsx`, which currently reuses the same generic boxes as demo's `OverviewPage.tsx`). |
| Demo Page | `client/src/hmi-definitions/demo/pages/OverviewPage.tsx` | NumericMon × 4, BooleanMon × 3, NumericSet × 2 with WidgetErrorBoundary wrappers. |
| Narya1 Tree | `client/src/hmi-definitions/Narya1/` | `tree.ts`: System Overview (`pages/SystemOverviewPage.tsx`, generic `HmiStatusBox`/`TrendStatusBox`/`ModuleStatusBox` from `shared/`), RF1 (`pages/RF1Page.tsx`, id `rf1`), plus the two Dev pages (Trends Perf, Trend Viewer), reused directly from `demo/pages/` — both are genuinely generic diagnostics, not demo-specific. Revisit once `demo/` is retired. |
| Narya1 RF1 Page | `client/src/hmi-definitions/Narya1/pages/RF1Page.tsx`, `Narya1/boxes/` | Covers the reference "RF Control" / "RF Phase" / "RF SpecA" pages, built from `Narya1_registry.csv` against the existing four core widgets. `Narya1/boxes/` is the first use of that directory — genuinely Narya1-specific boxes, not relocated from `shared/`. Two boxes are parameterized for exact-shape reuse: `Rf1PowerMonitorBox` (6 `RF1.Pwr_Mon.{Mag_1,Mag_2,Comb}.{Fwd,Ref}` channels, identical 9-field shape) and `Rf1InterlockBox` (4 `RF1.Dig_Intks.*` interlocks, identical 5-field shape). Scope matches what the reference screenshots show — the CSV's unshown advanced fields (`Freq.{By,In_A,In_B,Per,Tol}` and siblings on `Phase.Phase`/`PhPower.Power`/`Pulse.{Freq,Width}`) are not rendered. **Gaps pending new widgets** (tracked in `Docs/platform/platform_todo.md`): Phase X-Y scatter plot and frequency-mapped spectrum (interim: plain numeric fields; bin-index `SpectrumChart` against `RF1.SpecA.Spectrum`), label-lookup rendering for `RF1.Display.*`, `RF1.Module_Info.IP/Status` (String-type tags — `NumericMon` calls `.toFixed()`), and Close_App/Reboot command buttons (RF1's `cmd_str` contract unconfirmed). |
| Module Info Table | `client/src/components/ModuleInfoTable.tsx` | WS-driven. Resolves six abbreviated `HMI.Module_Info.*` paths (no root prefix — root-agnostic under any project) via a local `useSingleOptionalTag` hook: 0 matches → unresolved (no subscription, renders the existing null-tolerant greyed row — a missing `Module_Info` subtree is a normal permanent state, not an error); 1 match → used; >1 matches → warns once (path + every matched `tag_path`) and treated as unresolved rather than silently picking one. Does not throw, unlike `packages/widgets`' `useSingleTag`. Module ordering (`getModuleNames`) filters out tags with `module_id === 'unknown'` (no module ancestor) before computing the sequence — matches the server's (`hmi-tag-source.ts`) `t.module != null` filter exactly, so the two orderings agree by construction, not by relying on registry validation config. Renders per-module: name, status, handshake state, packets/s, KB/s, tags/pkt, packed-bit watchdog indicator. `HMI.Module_Info.Handshake` is optional and kept out of the length-mismatch check, so a registry applied before it existed shows "—". A non-N/A state is a button opening `HandshakeDetailsModal` (`client/src/components/`), which fetches `GET /api/v1/handshake/{module}` (`client/src/api/handshake.ts`, via `apiClient`) when opened and on Refresh. |
| Pole Page | `client/src/hmi-definitions/demo/pages/PolePage.tsx` | Demo page for the Pole MQTT module. `PoleBox` renders 5 separate module boxes: **App** (Py_Enable, Py_Connected, Stop_App command); **Speed** (Speed_Max/Accel_Max/Speed_Mon, Motor_En/Dir, Aux/End switches); **Position** (Position_Raw, Pos_Scale/Offset, Position); **Angle** (Angle_Raw, Angle_Offset, Angle_Mon); **Tests** (Pos_1/2 setpoints, Home/Go_to_Pos_1/Go_to_Pos_2 commands). `SpecABox` (`shared/SpecABox.tsx`) is a sibling component covering all `Pole.SpecA.*` tags: `FFT_Enable`/`Spectrum_En` `BooleanSet` under `Enable`; `Process_T`/`Pipe_Duty` `NumericMon`; `FFT_Size` `NumericSet`; `Center_Freq` `NumericSet` (single center-frequency setpoint, not a start/stop band); a `SpectrumChart` (from `@caro/widgets`) against `Pole.SpecA.Spectrum`, laid out in a flex row beside the parameter list, `yMax={2100}`. |

Client is a standard Vite React app. `vite.config.ts` proxies `/api` and `/ws` to the server on port 3003.

## Key Design Decisions

- **Tailwind v4 content discovery via `@source` directives in `client/src/index.css`.** Any workspace package whose source files use Tailwind class names must be listed there. Currently listed: `@caro/ui`, `@caro/widgets`, `@caro/hmi-context`, `@caro/trend-chart`. Without a `@source` entry, class strings from that package silently fail to compile.
- **No quality enum.** Null value = bad quality. Watchdog writes null on telemetry loss.
- **No per-tag timestamp in LKV.** Generation counters drive WS change detection. DB uses module-level timestamp from MQTT.
- **Widgets use `assetPath` string prop**, not pre-resolved TagDef. `useResolveAssetPath(assetPath)` does contiguous segment matching on dot-separated tag_path. Abbreviated paths supported.
- **Tag path resolution uses a prebuilt index.** `TagPathIndex` is built once when the tag map loads; `useResolveAssetPath` and `useTagGroup` both delegate to `tagPathIndex.resolve(path)` for O(1) contiguous-segment matches. Error semantics (no match / ambiguous match) enforced by the consuming hooks, not the index.
- **`useLiveValue` seeds state via `useState` initializer only.** The `subscribeLiveValue` callback fires synchronously on subscribe with the current LKV value, so no mount-time `setLiveValue` is needed. Avoids N redundant state updates per page mount on dense pages.
- **WS subscription is managed by a level-triggered reconciler.** `HmiContextProvider` maintains `desiredRef` (tag IDs the client wants, derived from `useLiveValue` refcounts) and `serverRef` (tag IDs the client has sent to the server). A microtask-batched `flush()` emits at most one `SUBSCRIBE` and one `UNSUBSCRIBE` per tick by diffing the two sets. Same-tick sub/unsub of a tag cancels out — zero wire messages. On reconnect, `serverRef` is cleared and flush emits one `SUBSCRIBE` with everything currently desired.
- **WS disconnect immediately nulls all live values.** On `ws.onclose` / `ws.onerror`, `HmiContextProvider` iterates every entry in `subscribersRef` and sets `valuesRef[tagId] = { value: null }`, notifying all subscriber callbacks synchronously. Widgets flip to bad-quality display (dashed red borders, `---`) the moment the connection drops. On reconnect the server sends a full SNAPSHOT in response to the re-SUBSCRIBE, repopulating all values.
- **Tag field resolution:** `eng_min`, `eng_max`, `unit`, `format`, `tag_name` are read directly from the resolved registry columns (`row.*` in `loadTagMap`). Never walk `meta` for these fields — `resolveRegistry` applies type-aware gating (e.g., suppressing unit/eng_min/eng_max on Booleans). Use `meta` only for structural data (`module_id` via `meta.find(m => m.type === 'module')`). See `loadTagMap` and `resolveRegistry.ts`.
- **Numeric formatting:** `resolveFormat(tag)` reads `tag.format` (registry-resolved string or null) and calls `compileFormat(pattern)` once at widget mount. Supports `"#.##"` (fixed-point) and `"#.##E+0"` (exponential) patterns. Never walks `meta`. Default: `"#.##"`.
- **WS pipeline is pull-based** (generation comparison per client per tick). DB pipeline is push-based (TelemetryIntake enqueues directly on every ingest call).
- **TelemetryIntake is the universal ingest entry point.** MqttBridge and HmiTagSource are both adapters. `ingest(moduleId, message)` handles LKV writes, watchdog updates, and DB pipeline enqueue.
- **HmiTagSource uses Proxy for typed property access** (e.g., `hmiTags.Module_Info_Module_Count = 11`). Property names derived from tag_path by stripping the module segment and joining remaining segments with `_`. Publishes to TelemetryIntake every 250ms (env: `HMI_PUBLISH_INTERVAL_MS`).
- **Auth is stubbed** — all connections accepted in dev mode.
- **Setpoint write flow:** Widget → `useTagWriter.write()` → `HmiContextProvider.writeTag()` → `POST /api/v1/tags/write` → `CmdController.writeValues()` → MQTT SET_VALUES → CMD_ACK → resolve/reject. On `accepted: false`, `writeTag()` throws so the error surfaces in the widget's error display.
- **Module command flow:** `useCommandSender.send(moduleId, cmdStr)` → `HmiContextProvider.sendCommand()` → `POST /api/v1/commands` → `CmdController.sendCommand()` → dispatches on module_type (MQTT: publish + await CMD_ACK 1s; HMI: RESET only). Client is module-type agnostic. Errors (TIMEOUT, COMMAND_REJECTED, COMMAND_NOT_SUPPORTED) surface through `useCommandSender.error()`.
- **Null LKV does not block setpoint writes.** `NumericSet` and `BooleanSet` remain interactive when `lv.value === null`. Write validation is server-side. Null is the normal initial state for any tag not yet receiving telemetry; it also occurs when the watchdog fires on a stalled module. `BooleanSet` with null value always writes `true` on click (toggle of null/false). `BooleanSet` with null value shows a dashed red border on the toggle track (matching `BooleanMon`'s null-state dot, `red-400` / `#f87171`) as a visual bad-quality indicator — the widget remains interactive.
- **No visual pending state on write widgets.** `BooleanSet` and `NumericSet` look identical during writes — no spinner, no opacity change. Double-click prevention only: button/input disabled while `isWriting` (via `useWriteGuard`).
- **`module_type` on TagDef.** All tag definitions include `module_type: string` (sourced from `tag_registry.module_type`). `CmdController` routes writes and commands on it: MQTT → broker, HMI → `HmiTagSource`, anything else → `MODULE_TYPE_NOT_SUPPORTED` per-tag result.
- **DbPipeline `queueDepth` is a pre-peek, tick-held snapshot.** Inside `flushOnce()`, `_queueDepthAtTick` is captured after the inFlight guard and before any splice — it reflects how many entries faced that tick, not the post-drain residual. `queueLength` (live queue size) is a separate accessor. The tick-held snapshot is stable for observers between ticks.
- **TelemetryIntake null-sentinel on watchdog stall.** When a trendable module transitions from healthy to stalled, TelemetryIntake enqueues a null value for each trendable tag (bad-quality sentinel). The FAULT status branch falls through to the COV enqueue (no early return) so stall transitions are always recorded.
- **TimescaleDbWriter string-drop log guard is per-instance.** `_strDropLogged` is an instance field, not module-level. In practice there is one writer per process, so the behaviour is equivalent; per-instance makes it unit-testable.
- **HmiTagSource never-sampled sentinel is `0`.** The DutyTracker / HmiTagSource "last-sampled" sentinel uses `0`, not `-1`. `performance.now()` is never exactly `0` at runtime, so this is unambiguous in practice.
- **Trends REST wire contract is v0.9 (start_time/end_time/bucket_count + min/max bands + raw prev).** Query params: `tag_ids`, `start_time`, `end_time`, `bucket_count` — no `bucket_s` or `tile_index` on the wire. `bucketS` is derived server-side. Aggregate response carries per-series `value`/`min`/`max` arrays; three-case rule classifies each bucket (mixed-null / empty-collapse / normal — see §6.5). Raw responses (`source: 'raw'`) carry `ts`/`value` and optional `prev: { ts, value }` per series; the discriminated union enforces no min/max leakage. bigints serialized as numbers via `serializeTile()`. See `Docs/hmi/trend-viewer/hmi_trend_viewer_spec.md` §6.
- **Trends API enforces N ≤ 8 tags per request.** The N≤8 cap (not 20) comes from gate-tested heap-scatter data — the cliff lives at N≈10–11. Charts with more than 8 plotted tags fan out into multiple parallel requests on the client. Route returns 400 (`INVALID_TAG_IDS`) on violation.
- **`HMI_TRENDS_GZIP=1` (default unset/off; any other value is off) gates Express `compression` middleware scoped to the `/api/v1/trends` mount only.** Does not affect other routes. Added for Phase A gzip A/B perf measurement against dense aggregate tile payloads.
- **TrendSnapshotScheduler uses `private` keyword (not `#`) and `dutyTracker.track(fn)` (not `track(label, fn)`).** Follows existing codebase convention. `DutyTracker.track` takes `fn: () => T` only — no label parameter.
- **TrendSnapshotScheduler piggyback flag is consumed at the top of `ingest()`, before the COV loop.** This ensures the snapshot row uses `message.timestamp` as `moduleTs` rather than `Date.now()`, anchoring the row to the module's own clock. The flag is set by the scheduler tick and consumed at most once per ingest call per module.
- **A registry missing the HMI's own diagnostic tags is a normal, permanent state, not a startup race.** `HmiTagSource`'s Proxy absorbs a write to any property with no matching registry tag (no maintained list of expected names — that was tried and reverted as a second source of truth that would drift from the templates) and reports each distinct name once. This is a deliberate trade: the throw was the only compile-time-adjacent typo protection that existed, and giving it up is accepted in exchange for a registry that hasn't instantiated a template (fully or at all) never crashing the server.
- **A WS SUBSCRIBE/UNSUBSCRIBE batch with some invalid tag ids is never discarded wholesale.** Only a non-array payload is malformed; `parseTagIdsArray` otherwise splits valid ids (subscribed) from invalid ones (logged by value). This exists because one caller subscribing to a bad id (historically: `ModuleInfoTable.tsx`'s hardcoded root prefix resolving to nothing, falling back to tag_id `0`) used to poison every other tag's subscription riding in the same batch.
- **Client and server module orderings (`getModuleNames`) must agree by construction, not by config.** Both filter to tags with a resolvable module ancestor before computing the sequence — server: `t.module != null`; client (`ModuleInfoTable.tsx`): `module_id !== 'unknown'` (the same condition, expressed via `tag-map.ts`'s null-vs-sentinel convention). An earlier version of this reasoning relied on `apps/tag-registry/server/.env`'s `VALIDATE_REQUIRED_PARENT_TYPES=module` to guarantee no tag lacks a module — that's apply-time config, says nothing about rows already in the table, and stops holding the moment someone edits the file. Do not reintroduce that shortcut.
- **An unregistered or null `projectRoot` renders the NavTree empty state — never a silent fallback to `demo`.** `Shell.tsx` looks up `PROJECT_ROOT` in `hmiDefinitionsRegistry`; a miss (including `null`, before `/config` resolves or if it fails) resolves the tree to `[]`. Falling back to `demo` would put an operator on the wrong machine's nav tree with no visible signal — an empty state that says "nothing loaded" is a safer failure than a tree that loads but is wrong.
- **Trend-viewer session persistence is namespaced per system, not just per `persistKey`.** `@caro/trend-chart` stays platform-ignorant (it never imports `@caro/hmi-context` or resolves `PROJECT_ROOT`); the client passes `storageScope={useProjectRoot() ?? 'unknown'}` into `TrendChartContainer`, which threads it down to `sessionPersistence.ts`'s `caro.<storageScope>.trend-viewer.session.<persistKey>` key. Without this, switching `PROJECT_ROOT` (see `Docs/platform/multi_project_runbook.md` §4) would show one system's saved trend session laid over another system's live data.
